# Конспектъ / Slovech

Telegram-бот и Mini App для расшифровки аудио, голосовых сообщений и YouTube-видео.
Результат — полный текст, структурированный конспект, главные мысли и экспорт DOCX.
Для английских записей доступен конспект на английском и русском.

## Структура

```text
slovech/          Python-приложение
  server.py       HTTP API и выдача Mini App
  bot.py          Запуск Telegram-бота
  worker.py       Обработка очереди заданий
  api/            HTTP-маршруты
  bot_handlers/   Обработчики Telegram
  core/           Настройки, модели, хранилище, авторизация и обработка медиа
  ai/             Gemini и OpenRouter
web/              Mini App: HTML, CSS и JavaScript без сборки
tests/            Python, JavaScript и браузерные тесты
scripts/          Резервные копии, миграция, диагностика и сборка релиза
deploy/           Caddy и настройки существующего VPS
docs/             Эксплуатационная документация
.github/          Автоматические проверки
```

Конфигурация разработки и Docker лежит в корне. Все команды ниже выполняются из корня проекта.
`var/` — локальные данные приложения, `backups/` — резервные копии, `dist/` — архивы релизов.
Эти каталоги не входят в Git и Docker-образ.

## Разработка

Для полного теста на Windows 11 без VPS: распакуйте `Slovech-Windows.zip` и запустите
`START-WINDOWS.cmd`. Бот, Mini App, AI-обработка и HTTPS-туннель работают в Docker.
При первом запуске нужны токен тестового бота и Gemini API key.
[Инструкция Windows](docs/windows-local.md).

Нужны Python 3.12, uv, Node.js/npm; для обработки аудио — FFmpeg и ffprobe.

```sh
make install
cp .env.example .env
make api
```

В `.env` укажите `BOT_TOKEN` и `GEMINI_API_KEYS`. В отдельных терминалах:

```sh
make bot
make worker
```

API: `http://127.0.0.1:8000`, проверка готовности: `/ready`, документация разработки: `/docs`.
Полноценный Mini App открывается из Telegram через HTTPS с подписанными данными входа.

В текущей рабочей папке сохранено окружение `.venv312`; Makefile использует его при наличии.
На новой машине после `make install` используется `.venv`. Явный выбор:
`make api PYTHON=.venv/bin/python`. Перенесённые окружения могут содержать устаревшие пути
в служебных скриптах, поэтому команды запускают инструменты через `python -m`.

## Проверки

```sh
make check
make test
npx playwright install chromium
make test-e2e
```

Тесты используют временные данные и подменяют AI-провайдеров. `make help` показывает доступные команды.

## Развёртывание и обслуживание

[Полная инструкция](docs/operations.md): Docker Compose, VPS, конфигурация, резервные копии,
восстановление, миграция и диагностика. Сборка архива исходников: `make release`.
Имена сервисов `api`, `bot`, `worker`, `caddy` и HTTP-адреса остались прежними.

При переходе со старой структуры `telegram_app/` корень приложения — теперь корень проекта.
Команды запуска: `python -m slovech.bot`, `python -m slovech.worker`,
`uvicorn slovech.server:app`. Файлы интерфейса находятся в `web/`, а HTTP-путь остаётся `/static/`.
При обновлении существующего Docker-развёртывания сохраняйте прежний каталог на сервере
и Compose project name, чтобы подключить прежние volumes с данными.

Прежние локальные SSH-скрипты и файл секретов сохранены в `.local/`; это частный архив,
исключённый из Git, Docker и релиза. Старый `sync.sh` содержит прежние пути и не является
командой развёртывания новой структуры. Инструкция в `docs/operations.md` — актуальный способ запуска.
