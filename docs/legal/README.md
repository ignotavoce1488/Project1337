# Приватность: эксплуатация и нерешённые юридические вопросы

Реквизиты пользователя внесены с его подтверждения. Это не заключение о полном соответствии 152-ФЗ. Статус НПД не меняет обязанностей оператора и не означает освобождения до какого-либо числа плательщиков.

## Реализовано

- Раздельное принятие соглашения и согласия, фиксация версии, времени и Telegram ID. Полные тексты редакций архивируются, в том числе первая опубликованная редакция.
- /revoke и /delete_me: подтверждение привязано к владельцу, действует 10 минут и используется один раз. Отказ от новой редакции сам по себе не удаляет прежнюю историю.
- Подтверждение блокирует доступ и новые задания, отменяет текущую обработку. После отмены новые результаты не записываются. Воркер очищает рабочую базу, связанные временные файлы и управляемые резервные копии. Незавершённый запрос сохраняется при ошибке и переживает перезапуск.
- SQLite secure_delete, VACUUM и checkpoint; резервные копии переписываются без удалённых строк. Это логическое уничтожение, не доказательство физического стирания с SSD или снимков хостинга.
- Промежуточные тексты удаляются при окончательном завершении; очередь и управляемые backup старше 7 дней очищаются, остаточное аудио старше суток убирается между заданиями. История удаляется после 365 дней неактивности.
- Минимальный журнал уничтожения без содержимого материалов хранится 3 календарных года. Его наличие не заменяет подписанный акт.
- Не обещается автоматическое удаление облачных Telegram-сообщений и внешних AI-копий.

## Что остаётся ответственностью оператора

1. Подтвердить фактическое расположение основной базы и резервных копий и выполнение требований локализации. IP-геолокация этого не доказывает.
2. Установить юридические лица, страны, правовые основания и условия обработки всех фактических получателей через AITUNNEL/OpenRouter. Названий моделей недостаточно. Действующий бесплатный NVIDIA endpoint ограничивает загрузку персональных и конфиденциальных данных. Пользователь решил сохранить маршруты; это не устраняет риск.
3. Проверить и исполнить требования к уведомлению РКН об обработке и отдельно о трансграничной передаче. Нет общего исключения «до 100 плательщиков» или «до регистрации ИП». Уведомления за оператора не подавались.
4. Вести учёт внешних выгрузок, snapshot хостинга и иных копий. Автоматическая очистка покрывает только DATA_DIR/backups/*.tar.gz и старые DATA_DIR/backup-*.tar.gz с единственным data/slovech.sqlite3. Перед восстановлением сверять выполненные удаления; не возвращать персональные данные из сторонней старой копии.
5. По запросу проверять дополнительные инфраструктурные логи и внешних получателей. Ротация Docker по размеру не задаёт срок в днях. Не утверждать об удалении во внешней системе без подтверждения.
6. Оформлять акт и выгрузку журнала по приказу РКН №179. Сервис формирует журнал и проект акта, но не подписывает за физическое лицо и не подтверждает действия поставщиков. Подписанный акт и выгрузку хранить защищённо 3 года; экспорт не попадёт под штатную ротацию самостоятельно.
7. Утвердить необходимые внутренние документы, меры защиты, порядок рассмотрения запросов и действий при инциденте. Проверить уведомления в сроки 24/72 часа при применимости.
8. До запуска оплаты подготовить отдельные условия тарифа и оплаты, чеки и порядок возврата с учётом статуса оператора.

## Выгрузка подтверждения удаления

При запросе смотреть не только сообщение бота, но и журнал. Сначала список без пользовательских идентификаторов:

```sh
docker compose exec worker python -m scripts.deletion_evidence --list
docker compose exec worker python -m scripts.deletion_evidence --record ID_ИЗ_СПИСКА --output /data/evidence-УНИКАЛЬНЫЙ_ID
```

Команды VPS дополняются `-p dictaphone_bot -f compose.yaml -f deploy/compose.vps.yaml`. Экспорт содержит персональные данные: скопировать в защищённое хранилище для актов, проверить scope и реквизиты обработчиков, подписать акт. На рабочем сервере не оставлять бесконтрольных дополнительных копий. Неподписанный Markdown не является автоматически подписанным электронным актом.

## Проверка работы

В тестовом окружении создать данные двух пользователей и резервную копию. Удалить первого: проверить отмену задания, недоступность Mini App, отсутствие текстов в активной базе и восстановленной копии, сохранность второго пользователя. При повреждённом backup подтверждение успеха не должно отправляться. После повторного запуска запрос должен продолжиться. Тесты: tests/test_privacy.py и tests/test_backup.py, без реальных платных AI-запросов.
